# Firestore & Storage Demo Data Import Guide

This guide explains how to import the generated demo data (`firestore-demo-seed.json`) into your Firebase project and upload the demo assets.

## 1. Import Firestore Data

The simplest way to import the generated JSON into your active Firebase project is to use a community tool like `node-firestore-import-export`.

### Step A: Export your Firebase Service Account Key
1. Go to your [Firebase Console](https://console.firebase.google.com/).
2. Navigate to **Project settings** > **Service accounts**.
3. Click **Generate new private key**.
4. Save the downloaded JSON file in the root of your project and rename it to `service-account.json`. (This file is added to `.gitignore` to prevent accidental commits).

### Step B: Import the JSON
Run the following commands in your terminal:

```bash
# 1. Install the tool globally (if you haven't already)
npm install -g node-firestore-import-export

# 2. Set the environment variable for your service account
# On Windows (PowerShell):
$env:GOOGLE_APPLICATION_CREDENTIALS="service-account.json"
# On Mac/Linux:
export GOOGLE_APPLICATION_CREDENTIALS="service-account.json"

# 3. Import the data
firestore-import -a service-account.json -b firestore-demo-seed.json
```

## 2. Upload Storage Assets

We have generated high-quality dummy assets located in the `storage-demo-assets/` directory. 

To associate them correctly:
1. Open the **Firebase Console** and go to **Storage**.
2. Upload the images from `storage-demo-assets/` directly to the root of your Storage bucket (or to the specific paths if your app expects them in folders).
3. Ensure the images are publicly accessible or accessible to authenticated users depending on your security rules.

The demo data references the dummy filenames (`demo_worker_profile.png`, `demo_customer_profile.png`, etc.). You can modify the URLs in `scripts/generate-demo-data.js` and re-run `node scripts/generate-demo-data.js` if you prefer to use the exact public URLs generated by your Firebase Storage bucket.

## 3. Verify the Demo Environment

1. Start the application (`npm run dev`).
2. Refer to `DEMO_CREDENTIALS.md` and log in with the various accounts.
3. Validate that dashboards populate with the mock data, charts reflect activity, and statuses correctly restrict or permit user actions.
